# M1.5：一个真实 Grok Bot 接进来 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans`. Steps use checkbox syntax.

**Goal:** 让一个真实的 Grok Bot（当前实例叫“扳子”）通过 bridge 接收 DSH Kanban 的卡、回写状态和评论。不是脚本冒充，不是 A2A。

**Architecture:** DSH Kanban 仍是 source of truth。本地 bridge 轮询分配给 builder 的卡，创建 GitHub issue，并向 Grok routine webhook 发任务；Grok Bot 在 issue 里回 JSON；bridge 校验后用 builder token 写回 Kanban。没有公网端口，没有 MCP，没有 A2A。

**Tech Stack:** Python 3.9+ stdlib（`unittest`、`urllib`、`subprocess`）、GitHub CLI `gh`、DSH `/kanban-api`、Grok Bot routine webhook。

**Spec:** `docs/superpowers/plans/2026-10-22-a2a-milestones.md` M1.5；现有 `dsh-grokbot-bridge` 的 TEST-003 issue bus。

## Global Constraints

- 只接一个 bot：`builder`（本实例“扳子”）。
- 一张卡 = 一个 GitHub issue。
- 不新增 A2A、MCP、tunnel、公网 endpoint。
- 不做 Planning、claim/lease、handoff、手机、门神。
- DSH Kanban 是权威；bridge 不保存第二份任务状态。
- token、webhook key、routine id 只来自环境变量或本地文件，不提交。
- 所有 Grok 回写必须是 JSON；prose 不执行。
- 同一 `message_id` / GitHub comment 只能处理一次。
- 失败时卡停在原状态，不能假 Done。

## 为什么不是 M4

M4 的 adapter 是 A2A 标准化（Agent Card / Task / Message / Artifact / 第二个 client）。

M1.5 只证明：

```text
真实 Grok Bot 收到一张卡 → 真实回写 → activity 是 builder
```

它可以是私有 bridge，不需要 A2A。

## 目标流程

```text
Silas → 掌柜 → 创建卡，assignee=builder
  ↓
bridge 轮询 /bootstrap
  ↓
创建 GitHub issue（task_request JSON）
  ↓
POST Grok routine webhook（issue + card + runUuid）
  ↓
Grok Bot 读 issue，执行，回 task_update/task_complete JSON
  ↓
bridge 轮询 issue comments
  ↓
校验 author / card / message_id
  ↓
用 builder token PATCH status + POST comment
  ↓
DSH activity = builder
```

## 协议

沿用 `bridge: "dsh-grokbot-v1"`，新增任务类型：

| type | 方向 | 用途 |
| --- | --- | --- |
| `task_request` | DSH → Grok | 一张卡交给 Grok |
| `task_update` | Grok → DSH | 进度 / 阻塞 / 证据 |
| `task_complete` | Grok → DSH | 完成 |
| `ack` | Grok → DSH | 已收到（可选） |

### task_request

```json
{
  "bridge": "dsh-grokbot-v1",
  "message_id": "uuid",
  "type": "task_request",
  "from": "dsh",
  "to": "grok",
  "agent": "builder",
  "card": "DSH-2",
  "task_id": "440e9040-1657-45bf-a945-0cadc6cabec0",
  "project_id": "dsh-kanban",
  "issue": 12,
  "run_uuid": "run-...",
  "title": "给看板加方案确认",
  "acceptance": "掌柜建卡，builder 能更新",
  "created_at": "2026-10-22T15:10:00+08:00"
}
```

### task_update / task_complete

```json
{
  "bridge": "dsh-grokbot-v1",
  "message_id": "uuid",
  "type": "task_update",
  "from": "grok",
  "to": "dsh",
  "agent": "builder",
  "card": "DSH-2",
  "task_id": "440e9040-1657-45bf-a945-0cadc6cabec0",
  "run_uuid": "run-...",
  "state": "in_progress",
  "note": "开始处理",
  "evidence": [],
  "created_at": "2026-10-22T15:11:00+08:00"
}
```

`state` 只允许：

```text
in_progress | blocked | done
```

`task_complete` 必须 `state=done`，至少一条 evidence（链接或文件路径）。

## Task 1: Envelope and validation

**Files:** `bridge/envelope.py`, `tests/test_envelope.py`

**Interfaces:**
- `parse_task_request(raw: dict) -> dict` — validates required fields; returns normalized.
- `parse_task_reply(raw: dict) -> dict` — validates type/state/evidence; raises `EnvelopeError`.
- `message_key(raw) -> str` — stable dedupe key.

Tests:

- accepts valid request/reply.
- rejects prose, missing `message_id`, wrong card/task_id, unknown state.
- `task_complete` without evidence fails.
- `task_update` with `state=done` fails (must use complete).

Run:

```bash
python3 -m unittest tests.test_envelope -v
```

## Task 6: Orchestrator

**Files:** `bridge/orchestrator.py`, `tests/test_orchestrator.py`

**One cycle:**

1. `bootstrap()`.
2. For each active task assigned to builder without mapping:
   - create issue with `task_request`;
   - `wake()`;
   - save issue + runUuid.
3. For each mapping:
   - list comments after `last_comment_id`;
   - parse JSON comments;
   - ignore non-allowlisted authors;
   - dedupe `message_id` and comment id;
   - apply `task_update` / `task_complete` to DSH;
   - write a DSH comment with note/evidence;
   - update state.
4. Never write Done without `task_complete` + evidence.

Tests with fakes:

- one card -> one issue -> one wake.
- duplicate comment -> one DSH update.
- old comment before `last_comment_id` ignored.
- task_complete sets done.
- bad JSON ignored and logged, does not mutate DSH.
- wrong author ignored.

Run:

```bash
python3 -m unittest tests.test_orchestrator -v
```

## Task 7: Real TEST-004

**Preconditions:**

- M1 live Kanban.
- builder token in `~/.dsh/kanban-agents.json`.
- GitHub repo `SilasSolivagus/dsh-grokbot-bridge`.
- Grok routine webhook + key.
- `gh auth status` OK.
- Allowlisted GitHub login in `GROK_GITHUB_LOGIN`.

Run bridge in foreground:

```bash
DSH_KANBAN_URL=http://127.0.0.1:61849/kanban-api \
DSH_KANBAN_BUILDER_TOKEN=... \
GROK_ROUTINE_WEBHOOK='https://api2.cursor.sh/automations/webhook/<routine-id>' \
GROK_ROUTINE_KEY='crsr_...' \
GROK_GITHUB_LOGIN='...' \
BRIDGE_REPO='SilasSolivagus/dsh-grokbot-bridge' \
python3 -m bridge.main --once
```

Create a card via 掌柜 assigned to builder. Expected:

```text
issue created
webhook accepted, runUuid stored
Grok Bot comments task_update
DSH card in_progress
DSH comment from builder
activity actor = builder
```

Then Grok comments task_complete with evidence:

```text
DSH card done
evidence comment present
issue closed
```

Prove it is real:

1. Stop the Grok routine; create a second card; bridge sends webhook but no comment; card stays Inbox.
2. Do not run the fake script; builder actor must come from Grok's comment.

Exit criteria:

- [ ] One real Grok routine receives the task.
- [ ] Grok comments a valid `task_update`.
- [ ] DSH activity actor is builder, not local user.
- [ ] Grok comments `task_complete`; card Done.
- [ ] Stop routine => no progress.
- [ ] Duplicate comment => no duplicate DSH update.
- [ ] No local port exposed.

## Risks

| Risk | Mitigation |
| --- | --- |
| Grok webhook returns runUuid but no completion callback | Poll GitHub issue; timeout `Needs you` later |
| Grok posts prose | Validator rejects; bridge comments error |
| Same account authors both sides | Allowlist + card/task_id + runUuid; production needs dedicated postman identity |
| Duplicate comments | `message_id` + comment id + state |
| Bridge down | Card stays; no fake Done |
| Token leak | env/local only; no logs |
| Grok can't access private issue | Add bot as repo collaborator; verify before TEST-004 |

## Definition of Done

> 一张真卡，被真的 Grok Bot 接走并回写。  
> 停掉 Grok，卡就不动。  
> 这时才可以说“扳子上板了”。
