# P1.1 — real SIGKILL restart probe

**Date:** 2026-10-23  
**Result:** PASS for crash recovery without duplicate prompt.

## Procedure

- loaded P1.1 supervisor in the live desktop profile
- created DSH-29 `Kill -9 restart probe` with a long `sleep 180` worker task
- waited until `in_progress` + lease held
- detached script ran `kill -9 <DSH app pid>`
- script reopened `DeepSeek Harness`

## After restart

The app restarted on a new port (`61849` -> `55654`), so the original script's
old-port check could not complete. Verification was performed manually against
the new port.

State:

```text
DSH-29: in_progress
version: 2
comments: 0
lease: active (360s)
worker parent/child: persisted
auth invalid token: 401
```

## What this proves

- SIGKILL does not lose the board.
- SIGKILL does not lose the lease.
- The restarted supervisor sees the active lease and does not issue a second
  prompt.
- Worker session ids remain persisted.
- Supervisor does not fake Done after a crash.

## What this does not prove

- Reclaim after the lease expires in this same run (separately proved live by
  DSH-27 with a real expired lease).
- The long child turn itself surviving SIGKILL; it did not need to.
- A crash during the lease write window.

## Cleanup

DSH-29 was archived. Profile returned to main; supervisor stopped.
