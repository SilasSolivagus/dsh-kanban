# P1.1 — restart / session reuse hardening

**Date:** 2026-10-23  
**Result:** PASS for session reuse across plugin reload.

## Problem

During the ten-card trial, a plugin reload during a running card changed the
worker session parent/child ids in one observation. The restart criterion was
therefore not proven.

## Fixes

1. `agentLoop.resume` now receives `AbortSignal.timeout(...)`.
2. Lease TTL is `worker.timeoutSeconds + 60`, so the prompt timeout always
   expires before the lease. This prevents reclaiming a still-running child.
3. Added a regression assertion that cold parent resume receives a signal.

## Live proof

Worker state before plugin reload:

```text
parent f22884b7-a5c1-4222-849a-9d8fa4dba7b9
child  15e2b948-4c07-4745-a01c-73c8e7a5e85b
```

Plugin disabled/enabled, then card DSH-21 (`Session reuse check`) was processed.

Result:

```text
status: done
same parent: true
same child:  true
comment author: builder
```

This proves the supervisor reuses the persisted child after a plugin reload.

## Still not tested
