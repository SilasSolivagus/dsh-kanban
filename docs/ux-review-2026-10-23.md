# DSH Kanban — UX 走查

日期：2026-10-23  
范围：看板首页、卡片抽屉、Needs you、创建流程、DSH 会话侧栏、P1 supervisor 可见性  
证据：live 看板截图、drawer 截图、live bootstrap、session 存储、源码

## 一句话结论

看板本身的视觉和信息层级是成立的；**产品上最大的缺口不是“看板做得不好”，而是“意图没有入口，worker 不可见”**。

当前它更像一个漂亮的人工看板，而不是一个“人对掌柜说意图、agent 去执行”的工作空间。

## 走查路径

### 1. 第一眼

好：

- 四列语义清楚，颜色有区分但不刺眼
- Needs you 是最强的一列，问题/阻塞能直接处理
- 卡片标题、项目、优先级、标签层级清楚
- 搜索、筛选、项目切换都在预期位置

问题：

- 没有“掌柜 / Office”入口。人不知道从哪里开始说“我想做什么”
- 没有 supervisor 状态：worker 是否在线、上次运行、失败没有可见反馈
- “3 个运行中”与 Running 2 不一致；因为 blocked 卡也算 running，但标签没有解释
- 每列都有 `+` 和底部“新建卡片”，重复且把注意力拉回手工建卡
- 大量空列，卡片很少时页面显得空，但不提供下一步引导

### 2. 我想放一件事进看板

当前只有两种方式：

1. 点列里的 `+` / “新建卡片”，直接填标题、描述、优先级
2. 去 DSH 聊天里找某个 session 说

这两种都不是产品设计里的“对掌柜说意图”。

问题：

- 手工建卡要求人先想清楚标题和验收，把“澄清”工作推回给人
- 没有“这是一件什么事 / 为什么现在做 / 什么算完成”的 brief 结构
- 建完卡后不知道谁来接；assignee 在 UI 里基本不可用

### 3. 卡在 Running

问题：

- 卡片不显示 assignee actor，只显示项目/优先级/标签
- 没有“扳子正在做 / 已领取 / lease 到什么时候 / 最后心跳”
- 没有 evidence 预览；人只能点开评论找 supervisor 的长评论
- blocked 卡留在 Running 的底层状态里，虽然会进 Needs you，但 Running 与 Needs you 的关系不直观

### 4. Needs you

好：

- 这是全产品最好的交互：问题内联选项、批准/拒绝、阻塞原因可见
- 自动汇聚比“人自己找哪张卡卡住了”强很多

问题：

- 问题、阻塞、评审三种语义混在一起，视觉上都是黄色
- worker blocked 后的动作只有“看评论”；没有“重试 / 改派 / 补充上下文”
- blocked 原因在卡面只显示一行，长原因被截断

### 5. Done / evidence

问题：

- evidence 只是 supervisor 评论里的一段文本，不是结构化字段
- 没有“证据已验证”标记，也没有命令/文件/链接的类型区分
- 人无法快速判断 Done 是真完成，还是 agent 自述

这直接削弱了产品最核心的承诺：**Done 必须有 evidence**。

### 6. 抽屉

问题：

- “负责人”仍然是禁用下拉，提示“当前仅支持指派给当前用户”
- 这与 M1/P1 的 actor 模型冲突；实际上 supervisor 已经把卡指派给 builder
- 没有 plan、evidence、worker、lease 字段
- 评论、活动、证据混在同一个流里

这是一个明显的“功能已上线，UI 还停在上一代”的问题。

### 7. DSH 会话侧栏

图中的“未分组 / 未命名”是 P1 测试产生的：

- `p1-builder` 下的 hidden parent sessions
- 父 session 是 root，没有标题，cwd 不在已注册 workspace 里
- 所以显示为“未分组”的两个“未命名”

这**不是用户数据**，是 supervisor 的内部运行时。

## 优先级

| 优先级 | 问题 | 影响 |
| --- | --- | --- |
| P0 | 没有掌柜 / Office 意图入口 | 产品故事不成立 |
| P0 | 内部 worker session 泄漏到侧栏 | 用户以为系统坏了 |
| P1 | 抽屉 assignee 仍是“本地用户” | 与 actor 模型矛盾 |
| P1 | evidence 不是一等公民 | Done 不可信 |
| P1 | supervisor/worker 状态不可见 | 人不知道 agent 是否在工作 |
| P2 | 首屏空状态无引导 | 新用户不知道下一步 |
| P2 | 每列重复建卡入口 | 视觉噪音 |
| P2 | “运行中”计数语义不清 | 信任感下降 |

## 掌柜应该在哪里

产品原则是“一个入口；人只对 office agent / board 说意图”。

我的建议：

- **掌柜 = 一个固定的 DSH 会话**，名字叫 `掌柜 · Office`，固定在侧栏
- 看板顶部放一个主按钮：`找掌柜` / `Brief`
- 点它打开这个会话，而不是在看板里再做一个聊天框
- 看板只负责状态和证据；意图、澄清、拆卡都在 Office 会话里完成
- 卡片评论只用于决策、阻塞和验收，不承担“聊需求”

推荐流程：

```text
Silas 在 Office 会话说意图
  → 掌柜澄清目标 / 验收 / 优先级
  → 掌柜建 1..N 张卡，assignee=builder
  → supervisor 领取
  → 扳子在卡上执行
  → evidence 回写
  → Done；卡住则 Needs you
```

不建议：

- 在看板里塞一个独立聊天窗（重复 DSH 会话能力）
- 让人直接建卡再让 agent 猜意图
- 把“和掌柜沟通”放进卡片评论
